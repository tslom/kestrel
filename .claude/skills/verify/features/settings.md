# Settings (sheet `settings`), Look lab, theme

## Sub-features
- Claude accounts: every saved account in priority order with its 5h and week meters (ceiling marks, reset times), rename, ↑ ↓, Use, rules (5h and week ceilings, "only when its 5h window is idle", on), Forget, "Back to auto" while one is held, "Recent switches". The console bar's account chip (shows with two or more accounts) opens the same list as a menu with a one-click switch.
- Settings: Claude account (sign in / add account / cancel), Claude Code version and update, theme (System / Light / Dark), desk layout (Rooms / Classic), agents on the desk (Orbs / Cursors / Off), the permission select for new tabs; Usage (auto-resume, Stats for nerds, Model usage → Open); Scheduled prompts (list, Pause / Resume, Delete, New scheduled prompt form); link to Sources.
- Models: what each Claude account may run (a ✓ / ✕ per family, "Recheck now" probes again), then a default per mode (Vault / Study / Dev tabs), per tier (Plan / Decide / Grunt) and per outside provider, each saying what it runs and, under the row, what runs instead when the default is gone or the account in use can't run it; a line saying when each list was fetched.
- Providers: Claude, Antigravity, ChatGPT (Codex) with installed / signed in / on-off, "Good for" and "Better than Claude at" lines, the install command and the ways to sign in ("Sign in, either way:" with a bullet each) when one isn't ready, "Check again".
- Provider accounts (Antigravity, Codex): each account's name, email · plan · "school account", signed in or out, ↑ ↓ order; Codex's 5h / Week meters and a Month credits meter ("N of 6,500 credits used this month"), Allowance and Stop at credits, a window ceiling; agy's runs this month; "Allowed for" personal / learning / client & commercial; on; Forget. "Add account" (optional name) starts the CLI's own sign-in and the browser opens on its page (ChatGPT's, opened by Kestrel; Google's, opened by agy): the panel says "Your browser needs you now", with "Open it again" and a link for Codex, the time left and Cancel, and saves itself when the callback lands. Codex also has "Use a device code instead", which shows a link and code with Copy.
- Stats for nerds: on, each reply's footer gains "Ns to first token · N tok/s · N calls" (from the next reply).
- Scheduled prompts: a due one opens as a new tab on its own (lib/schedules.js, once a minute and on load), starting on a brief that names the prompt and says if it's late.
- Look lab: choose a layout, pin A/B and flip, agent style and a session replay, map ground, colour, vote ("Like it" / "Not it" / "Just the note").
- Themes Kestrel made (console tool theme_set): each is a chip after the built-in colours in the lab's Colour row, with "Specimen" and "Remove it" under the row while one is on. Which one is on is the server's (`GET /api/looks/themes` → `active`), not localStorage.
- Theme specimen: `/#specimen/dark/<theme id or baseline>` renders `src/ui/ThemeSpecimen.jsx` instead of the desk: every colour role in use, no console, no cards. It is what theme_set screenshots.
- Palette theme toggle.

## How to get to it (user POV)
- `⌘K Settings`, `⌘K Look lab`, `⌘K Use the dark theme` (reads `⌘K Use the light theme` when already dark).
- On the classic desk `.look-chip` shows. ⌥⇧L flips A/B, ⌥⇧M steps the map ground, ⌥⇧A the agent style.

## Driving it with Playwright
- Settings: `div.settings` (a glance chip is a `button.settings` too), `section.set-sec`, `.set-row`, `.set-what`, `.set-how`, `.set-seg` (role=radiogroup, buttons role=radio, `.on`), `select.set-select`, `.set-note` (`.good` / `.bad`).
- Look lab: `.look-lab` (role=dialog), `.ll-x`, `.ll-list`, `button.ll-pick` (aria-checked), `.ll-ab button` (aria-pressed), `.ll-seg`, `.ll-axis`, `.ll-btns button`, `.ll-saved`.
- Theme: localStorage `theme` = `"dark"`, which sets `data-theme` on `<html>`. Look-lab state is `data-look` / `data-layout` / `data-map` / `data-agents` on `<html>`.
- Themes: `.ll-chips[aria-label="Colour"] button` (a theme's has `.ll-theme-swatch`), `button.ll-link` removes the one that's on. `data-look` is the theme's id (`theme-warm-dusk`), its CSS is in `style#look-themes`. Specimen: `.spec`, `.spec-swatches`; ready when `<html>` has `data-specimen="ready"`. The tool's own picture: `python -m app.webshot <loopback url> out.png` (off-screen WKWebView). To drive the tool without a model, call `console_tools.theme_set.handler({...})` under `DASHBOARD_DATA_DIR=/tmp/x BACKEND_PORT=<a scratch backend serving a fresh dist>`.
- Models: the `section.set-sec` whose h3 reads Models; `.model-access li` (`.on` = the account in use) with `.ma-fam` (`.yes` / `.no`), `.set-sub` group heads, selects by `aria-label` ("dev model", "plan model", "Antigravity model"), fallback notes `.set-note.warn`. `GET /api/models`, `PUT /api/models/defaults` ({key, value}; "" clears), `POST /api/models/refresh` (probes every account: real model calls, a few hundred tokens). A rig backend under `--lifespan off` has no accounts tick, so set `claude_quota.set_active` before serving, or nothing shows as refused.
- Providers: `.prov` (one per provider, `data-provider`), `.prov-state` (`.ready`), `.prov-need` with `.prov-steps`; its on/off is a `.set-seg`; `.prov-good`. `GET /api/delegates/providers` (each provider's `accounts` and `signing_in`; `login` is the ways to sign in).
- Provider accounts: `.prov-accts`, `.acct` with `data-account`, `.acct-check` (allowed-for and on), `.acct-cap input`, `.prov-acct-line`; `.prov-add` with `.prov-add-name`; a sign-in under way is `.prov-login`: `.prov-turn` ("Your browser needs you now") once the page opened, `.prov-left` the time left, `.prov-code` for a device code. Writes: `POST /api/delegates/providers/{p}/login` (`way`: omitted = browser, or `device`), `GET` it to poll, `POST …/login/reopen`, `DELETE …/login`, `PATCH /api/delegates/accounts/{id}`, `POST /api/delegates/providers/{p}/order`, `DELETE /api/delegates/accounts/{id}`. In a rig, route the providers GET to a fixture (a Codex school account with windows and credits, a `signing_in` per provider) and route the login GET too, or its poll replaces the fixture.
- `GET /api/console/account`, `GET /api/console/cli`, `GET /api/looks`.
- Claude accounts: `.accts`, `.acct` (`.active`, `.off`), `.acct-name-in`, `.acct-meter` (`.over`), `.acct-cap input`, `.acct-check`, `.acct-log`. Bar chip `.acct-chip`, menu rows `.acct-row`. `GET /api/console/accounts`; writes are `POST …/{uuid}/use`, `POST …/auto`, `PATCH …/{uuid}`, `POST …/order`, `DELETE …/{uuid}`. In a rig, `page.route` the GET to a fixture with three accounts (real data may have one, and the chip hides below two) and fake every write.
- Scheduled prompts: `.sched`, `.sched-row` (`.off` when paused), `.sched-mode`, `.sched-btns`, `form.sched-new`, `.sched-prompt`, `.sched-when`, `.sched-days` (buttons aria-pressed), `.set-input`. `GET/POST /api/schedules`, `GET /api/schedules/due`, `POST /api/schedules/{id}/claim|ran|enabled`, `DELETE /api/schedules/{id}`.
- Stats for nerds: localStorage `console_nerd_stats` = `"1"`; the footer text matches /tok\/s/.
- Proof for the runner: put a schedule's `next_at` in the past (in a DB copy), load the page, and watch `runs` go to 1 and a new `.st-tab` start on the brief.

## Gotchas
- Screenshots are judged in dark mode (CLAUDE.md, "Dark mode first"). Use `colorScheme: "dark"` on the context **and** `localStorage.theme = "dark"` before load: `setTheme` removes the key when the choice matches the system, so neither alone is reliable.
- A scheduled prompt that comes due opens a real tab and runs a real turn (model usage). Creating one in the rig writes app.db: use a DB copy, or delete it after.
- Picking any Colour chip while a theme is on writes `look_themes.active` in app.db, and "Remove it" deletes the theme's row. The specimen page never runs `requestAnimationFrame` work in the tool's screenshot (the window is never shown), so don't gate its ready flag on a frame.
- Claude accounts: "Use" rewrites the CLI's login slot in the Keychain (machine-wide, terminal included), and Forget deletes a saved login. Never click them against the real backend; route them.
- "Add account" starts a real sign-in: a new home under `~/.kestrel/agents/accounts`, and the user's browser opens on a ChatGPT or Google page. Never click it in a rig; route it. Forget deletes the account's home and its token.
- Votes are real app.db rows. "Continue in browser" changes the CLI login machine-wide. "Update to X" runs a real Claude Code update. Selects write localStorage at once. A provider's On/Off writes `delegate_providers` in app.db; put it back.
